# Changelog

## 2026-10-18 — 1.0.5

- `pogo convert` writes the encrypted file, reads it back, and decrypts it before it will remove the plaintext. It then asks `Delete the original <file>? [y/N]` on the controlling terminal. The default is No. Only `y` or `yes` deletes the file. Enter, any other answer, EOF, and a session with no terminal keep it. The question is not read from stdin, so it still works when `--key-stdin` is a pipe. `--delete-original` removes the plaintext without asking. `--keep-original` leaves it and does not ask. A failed conversion or a failed decrypt check never deletes the plaintext. The remove is a normal delete, not a secure wipe. `encrypt` still does not ask and does not delete.

## 2026-10-17 — 1.0.4

- Added `pogo upgrade`. It reads the latest GitHub release of JacksonJRay/pogo, or the release named by `--version`, downloads `pogo-<os>-<arch>` and `SHA256SUMS` over HTTPS, checks the SHA256, and replaces the running binary only after the new file's `version` command prints the expected version. Already current prints `pogo 1.0.4 is the latest version` and exits 0. Pogo does not downgrade unless `--version` names an older release. `--check` does not install and exits 10 when a different release would be installed, including when the binary is on a Nix or Guix store path. A terminal asks `Install? [y/N]`. With no terminal, `--yes` is required. A permission error or an install onto a Nix or Guix store path leaves the original binary in place. If GitHub cannot be reached, Pogo exits 1 with `pogo: could not reach GitHub to check for updates:` and leaves the binary untouched. Machines with no CA certificates use a built-in Mozilla root set; system certificates and `SSL_CERT_FILE` / `SSL_CERT_DIR` still win when they are present. `GITHUB_TOKEN` is sent only to `api.github.com`. `POGO_UPGRADE_API` is a test-only API base.
- Creating a passphrase (`init`, `encrypt`, `convert`, and the new passphrase for `rekey`) asks twice through whichever backend is in use: `New passphrase for <file>` and `Confirm new passphrase for <file>`. The length and blank checks run after the first entry and before the confirmation prompt. A too-short, blank, or mismatched passphrase exits 4 and writes nothing. Cancel or timeout on either prompt writes nothing. `rekey` asks for the current passphrase, checks that it decrypts, and only then asks for the new one twice. `--key-stdin` and `--key-env` stay one-shot. `--key-file` and `--new-key-file` stay rejected.
- The editor passphrase box names which question it is. Opening a file still uses `pogo-passphrase-for-<file>.invalid`. A new passphrase uses `pogo-new-passphrase-for-<file>.invalid`, and the confirmation uses `pogo-confirm-passphrase-for-<file>.invalid`. The username stays `pogo-passphrase`.
- `pogo edit` and `pogo init` can open an editor when stdin is not a terminal. The order is `$POGO_EDITOR`, then the editor's own CLI with `--wait` when `VSCODE_IPC_HOOK_CLI` is set (bundled remote CLI, then `code-server`, `code`, `cursor`, `codium`, unless `TERM_PROGRAM` names one of those), then `$EDITOR` or `$VISUAL` when it waits or is not a terminal editor, then a known waiting GUI editor on a real display. `vim` and `nano` are skipped without a terminal. A script in `EDITOR` still runs. If nothing can open a window, Pogo exits 1 and does not print the decrypted file. The opened line names the encrypted file, for example `Pogo opened e.enc (decrypted) in the editor. Save and close the tab to continue (pogo waits up to 10 minutes; Ctrl+C to stop).` With no terminal and a GUI or remote-CLI editor, the default wait is 10 minutes. `POGO_EDIT_TIMEOUT` is a number of seconds and `0` waits until the editor exits. A terminal with the variable unset still waits until the editor exits. If the file was saved before the deadline, Pogo encrypts that text. The temp file is mode 0600 in a mode 0700 directory under `$XDG_RUNTIME_DIR`, `/dev/shm`, or the system temp directory, and it is removed on success, editor failure, signals, and timeout. Unchanged text does not rewrite the encrypted file. Invalid env syntax exits 3 when there is no terminal to fix it.
- Agent text tells the person not to guess or search the filesystem for a passphrase, and not to suggest `printf 'PASSPHRASE' | pogo ...`, because that stores the passphrase in shell history. Use a secret manager or keychain CLI instead.
- `pogo doctor` reports the passphrase backend for init, edit, run, encrypt, decrypt, convert, and rekey, and which editor would be used. The editor line does not change the exit code.

## 2026-10-17 — 1.0.3

- When stdin is not a terminal and no key flag is set, Pogo asks through a prompt already on the machine. It tries `POGO_ASKPASS`, then the editor Git prompt (`VSCODE_GIT_IPC_HANDLE`, used by code-server, VS Code, and Cursor), then a desktop askpass when `WAYLAND_DISPLAY`, `DISPLAY`, or `MIR_SOCKET` is set. `gcr4-ssh-askpass` is used only when `GCR_SSH_ASKPASS_SOCKET` is present, because that program relays to GNOME and does not open a dialog by itself. A helper that cannot open a display is skipped. A real terminal still uses the echo-off prompt and waits until you type or press Ctrl-C. `POGO_TTY_TIMEOUT` is an optional number of seconds for a terminal nobody is watching. `--key-env` and `--key-stdin` are unchanged.
- If nothing can ask, Pogo exits 1. The first line is `pogo: no way to ask for the passphrase here`. The message lists what was checked and the ways forward, in order: a terminal, `docker run -it`, `--key-stdin` from a secret manager, `POGO_ASKPASS`, and `--key-env` as a last resort. The last line tells an agent not to ask for the passphrase in chat.
- `pogo doctor` reports which prompt would be used and does not ask. Exit 0 when one is available, exit 1 when not. `POGO_DEBUG=1` prints detection decisions on stderr, including `pogo: stdin is not a terminal` on `run` and on `doctor`.
- If the editor accepts the askpass request and does not answer, Pogo waits and then exits 1 with `pogo: the editor prompt got no answer within the timeout`. It does not open a desktop dialog afterward. A missing socket or a refused connection still falls through. `POGO_PROMPT_TIMEOUT` is a number of seconds for that wait and for `POGO_ASKPASS` and desktop dialogs. Unset, it stays two minutes. `POGO_TTY_TIMEOUT` is still only the terminal.
- When `POGO_ASKPASS` or a desktop askpass hits that timeout, Pogo exits 1 with `pogo: the POGO_ASKPASS prompt got no answer within the timeout` or `pogo: the <program> prompt got no answer within the timeout`, then the same ways forward. It does not open another dialog. A helper that exits non-zero, including Escape, still says the prompt was cancelled.
- Cursor's box is titled from a fake host, `pogo-passphrase-for-<file>.invalid`, with username `pogo-passphrase`. The name does not resolve. code-server and VS Code still show Pogo's full prompt text. Stderr says which file the editor box is for.
- A local `DISPLAY` (`:N` or `unix:N`) is used only when `/tmp/.X11-unix/XN` exists. `WAYLAND_DISPLAY` is used only when that socket exists. TCP displays such as `localhost:10.0` are not checked. A missing local socket is reported as `display set but no X server socket`.
- `--key-file` and `--new-key-file` stay rejected.

## 2026-10-17 — 1.0.2

- Opening an existing file (`run`, `decrypt`, `edit`, and the current passphrase for `rekey`) accepts any passphrase whose length is greater than 0. Only an empty passphrase is rejected (exit 4). A wrong passphrase still fails with exit 2. `--allow-short-passphrase` is still accepted on those commands and has no effect; Pogo does not print the short-passphrase warning on the open path. `edit` re-saves with the same passphrase and does not apply the creation minimum again.
- Creating a passphrase (`init`, `encrypt`, `convert`, and the new passphrase for `rekey`) still requires 15 characters. `--allow-short-passphrase` is the only way to skip that minimum (one non-whitespace character is enough). Empty or whitespace-only is still rejected, and the short-passphrase warning is still printed. The length check still runs before Argon2.
- Breaking: `--min-length` was removed.

## 2026-10-17 — 1.0.1

- Added `--allow-short-passphrase`. It skips the 15-character minimum on `init`, `edit`, `run`, `encrypt`, `decrypt`, `convert`, and `rekey` (the current passphrase and the new one). A passphrase is still required: empty or whitespace-only is rejected with exit 4. The flag prints one warning line on stderr: short passphrases are much easier to guess. That warning is not written to stdout.
- `--min-length` already accepts a number as low as 1 and warns below 15. The new flag is that same choice without a number. If both are set, `--min-length` is the minimum.
- Decryption of a file that already uses a passphrase of 15 or more characters is unchanged. Without the flag, a short passphrase still exits 4. A wrong passphrase still exits 2.
- `--key-file` and `--new-key-file` stay rejected with exit 1.
